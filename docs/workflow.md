# Workflow настройки

## 1. Перед началом

Перед любыми изменениями сохранить:

- исходную ROM;
- последнюю заведомо рабочую ROM;
- definition, с которым ROM открывается в RomRaider;
- конфигурацию логгера;
- краткое описание железа автомобиля и топлива.

Не считать ROM стабильной только потому, что ECU принял запись и двигатель завёлся.

## 2. Один этап — одна группа изменений

Хороший пример:

```text
MAF: correction 3.40-3.65 V
```

Плохой пример:

```text
MAF + injector scalar + ignition + fueling + TGV
```

Чем меньше независимых переменных изменено одновременно, тем легче понять причину результата.

## 3. Базовая проверка после прошивки

Сразу после записи проверить:

1. запуск;
2. реакцию на педаль;
3. устойчивость ХХ;
4. наличие DTC;
5. температуры;
6. A/F Correction и A/F Learning;
7. IAM, FBKC и FLKC;
8. адекватность MAF Voltage / MAF g/s / Engine Load.

Если двигатель троит, не реагирует на газ или параметры явно нелогичны — прекращать тест и возвращаться на последнюю рабочую ROM.

## 4. MAF Scaling

Настраивать поэтапно.

### Closed Loop

Для нижней и средней части MAF использовать стабильные режимы CL и оценивать суммарную топливную ошибку по A/F Correction + A/F Learning.

Не оценивать точку по одному мгновенному значению. Нужна группа выборок в близком диапазоне MAF Voltage / g/s.

### Open Loop

Верх MAF проверять под нагрузкой по широкополосной лямбде.

При анализе сравнивать не только фактический AFR с `Primary Open Loop Fueling`, а с реально сформированной целью/итоговым fueling с учётом доступных коррекций ECU.

После изменения верхней части повторно проверить соседние диапазоны, чтобы не создать ступеньку в кривой MAF.

## 5. Injector Scaling / Latency

Не использовать injector scalar как быстрый способ исправить ошибку MAF, если MAF ещё не стабилизирован.

После изменения injector scalar проверить минимум:

- ХХ;
- малую нагрузку;
- cruise;
- CL trims;
- переход CL → OL;
- AFR под нагрузкой.

Если ошибка зависит от pulse width/напряжения, отдельно анализировать latency, а не пытаться исправить всё одним scalar.

## 6. Fueling

После стабилизации измерения воздуха и форсунок переходить к `Primary Open Loop Fueling` и связанным компенсациям.

Важно: значение в основной OL-таблице не обязано один в один совпадать с фактической смесью. Перед выводом искать действующие компенсации и итоговую цель fueling.

## 7. Ignition / Knock

После изменения смеси повторно проверить зажигание: изменение AFR влияет на условия детонации.

Контролировать:

- IAM;
- FBKC;
- FLKC;
- нагрузку;
- обороты;
- throttle;
- AFR;
- температуры.

Не делать вывод о детонации только по одному параметру без привязки к режиму работы.

## 8. Stable checkpoint

Версию можно пометить stable/confirmed, если:

- автомобиль нормально запускается;
- нет аномального поведения дросселя/ХХ;
- нет новых критичных DTC;
- базовые коррекции понятны;
- записан и проанализирован лог соответствующего режима;
- известен точный diff относительно предыдущей версии.
