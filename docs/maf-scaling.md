# MAF Scaling — рабочий процесс

## Цель

Настроить кривую MAF так, чтобы рассчитанный ECU расход воздуха соответствовал реальному количеству воздуха и топливная система не компенсировала систематическую ошибку измерения.

## 1. Не смешивать CL и OL

### Closed Loop

Использовать для нижней/средней части диапазона MAF.

Основные параметры:

- MAF Voltage;
- MAF g/s;
- A/F Correction #1;
- A/F Learning #1;
- RPM;
- Engine Load;
- throttle;
- CL/OL state;
- ECT;
- battery voltage.

### Точная формула суммарного trim

В проекте для MAF Scaling 11 использовалась мультипликативная формула:

```text
combined_trim = (1 + A/F Correction / 100)
              × (1 + A/F Learning / 100)
              - 1
```

Если нужен результат в процентах:

```text
combined_trim_% = combined_trim × 100
```

Далее базовая математическая поправка точки MAF:

```text
new_MAF = old_MAF × (1 + correction_% / 100)
```

Пример логики:

- положительная суммарная коррекция → ECU добавляет топливо → MAF обычно занижает воздух → scaling увеличивается;
- отрицательная коррекция → ECU убирает топливо → MAF обычно завышает воздух → scaling уменьшается.

Это только базовый расчёт. Итоговая применённая поправка может быть меньше из-за разброса данных, малого числа выборок и необходимости сглаживания кривой.

## 2. Фильтр стабильного CL из MAF Scaling 11

В реально использованной методике применялись следующие критерии отбора:

```text
CL/OL status:                    8 = Closed Loop
ECT:                             85–105 °C
Непрерывный CL:                  ≥ 0.5 с до и после точки
Скорость изменения MAF Voltage: ≤ 0.20 В/с
Скорость изменения throttle:    ≤ 3 %/с
Скорость изменения RPM:         ≤ 250 rpm/с
|A/F Correction|:               ≤ 15 %
Battery voltage:                 ≥ 13 В
```

Смысл фильтра — убрать переходные режимы, tip-in, нестабильный прогрев и быстрые изменения нагрузки.

Не корректировать точку по одному сэмплу. Данные группируются по близкому MAF Voltage, после чего оцениваются median/robust trim и разброс.

## 3. Практический результат MAF Scaling 11

В одном из контрольных логов:

- полезная продолжительность: около 41.5 мин;
- стабильных CL-строк: более 7000;
- уверенно покрытый диапазон: примерно 1.25–2.66 В;
- до ~2.89 В данные были, но верхняя часть имела низкую выборку;
- выше ~3.0 В этим CL-логом MAF не калибровался.

Основное уменьшение MAF тогда пришлось на область примерно 1.25–2.03 В, где сохранялся отрицательный trim. В зоне около 2.11–2.77 В изменения были небольшими, потому что участок уже находился близко к нулю.

Практическое правило: **нет хорошей выборки — нет агрессивной правки**.

## 4. Open Loop

Верхнюю часть MAF оценивать по wideband AFR.

Если известна **реальная итоговая цель смеси**, базовая поправка:

```text
new_MAF ≈ old_MAF × (actual_AFR / target_AFR)
```

Пример:

```text
target = 11.5
actual = 12.0
12.0 / 11.5 = 1.0435
```

То есть исходную точку MAF увеличить примерно на 4.35%.

Если смесь богаче цели, коэффициент получится меньше 1 и scaling уменьшается.

## 5. Что считать target AFR

Не использовать `Primary Open Loop Fueling` как гарантированную фактическую цель без проверки.

До расчёта поправки проверить:

- Final Fueling Base / итоговую цель, если доступна;
- A/F Learning, которое может сохранять влияние;
- IAT/ECT-related compensation;
- enrichment/transition compensation;
- другие активные fueling compensations.

Иначе можно ошибочно исправлять MAF за компенсацию, которая относится к другой подсистеме.

## 6. Wideband delay

Широкополосный датчик и особенно внешний WB через USB могут иметь задержку относительно параметров ECU.

Поэтому:

- не сопоставлять AFR с MAF Voltage сэмпл-в-сэмпл без проверки задержки;
- использовать достаточно длинные стабильные участки;
- при разгоне учитывать временной сдвиг WB относительно RPM/Load/MAF.

## 7. Сглаживание

После расчёта поправок:

1. не создавать резких локальных ступеней;
2. проверить монотонность MAF curve;
3. учитывать соседние точки;
4. снижать величину правки при слабой/шумной выборке;
5. не трогать OL-зону на основании CL-лога;
6. после сглаживания обязательно записать новый лог.

## 8. Отдельный урок из MAF Scaling 11

Один из полученных тогда BIN оказался неполным: размер 196608 байт вместо полного 524288-байтного образа, а диапазон `0x10000–0x2FFFF` был заполнен нулями. Калибровочной области MAF в таком файле не было.

Такой файл нельзя использовать для безопасной прямой правки таблиц. Перед любым binary patch сначала проверяется размер и целостность ROM.

## 9. Когда остановиться

MAF можно считать достаточно стабильным для перехода к следующему этапу, когда:

- CL trims не показывают устойчивую систематическую ошибку по диапазонам;
- OL WB близок к реальной целевой смеси;
- нет выраженных скачков ошибки на соседних MAF Voltage;
- изменения MAF не используются для компенсации очевидной ошибки injector scalar/latency или другой таблицы.

## 10. Что фиксировать в commit/version

Для каждой итерации записывать:

```text
Voltage range:
Old scaling:
Sample count:
Median / robust trim:
Calculated correction:
Applied correction:
Reason for smoothing/limiting correction:
Log before:
Log after:
Result:
```

Это позволяет потом понять не только конечные значения, но и почему они появились.
