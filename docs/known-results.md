# Известные результаты проекта

Здесь фиксируются наблюдения, подтверждённые реальными логами/тестами проекта или непосредственной проверкой структуры полного A2WC012E BIN. Они не превращаются автоматически в универсальные правила для других ROM.

## Автомобиль / ECU / ROM

- Автомобиль проекта: **Subaru Forester STI SG9, JDM / RHD**.
- Основная исследуемая калибровка: **A2WC012E**.
- `sg9` в именах исторических BIN соответствует реальной модели автомобиля проекта.
- Для работы используется RomRaider и соответствующие XML definitions.
- Перед прямой правкой BIN адрес таблицы должен быть отдельно подтверждён.
- Calibration offsets, code hooks и runtime RAM addresses ведутся раздельно.

## Address research

### ✅ CONFIRMED — две последовательные Base Timing Idle tables

В полном A2WC012E BIN подтверждена структура:

```text
ECT axis:            0x5AFDC
Base Timing Idle A:  0x5B157
Base Timing Idle B:  0x5B167
Points:              16 + 16
```

Вторая таблица начинается сразу после 16 байт первой и корректно декодируется по общей ECT axis.

Что **не** подтверждено этим фактом: конкретное условие выбора A/B. Название `In-Gear` и возможная связь с TGV остаются рабочими гипотезами.

### ✅ CONFIRMED — MAF Scaling offsets

```text
MAF Voltage axis: 0x5E538
MAF Flow table:   0x5E610
Points:           54
```

Контрольный diff MAF Scaling показал изменения только внутри ожидаемой flow table.

## MAF / Fueling

### ✅ CONFIRMED — Primary OL не равен автоматически фактическому AFR

В одном из разборов при примерно 3036 rpm и Engine Load около 2.38 фактическая смесь по датчику была около 11.02, тогда как область `Primary Open Loop Fueling` давала значение примерно 12.5.

Вывод: при таком расхождении нельзя сразу править MAF только по разнице между WB и Primary OL. Сначала нужно понять итоговую цель смеси и действующие компенсации.

### ✅ CONFIRMED — A/F Learning может влиять на анализ перехода в OL

В проектном логе после сброса ECU успела накопиться коррекция порядка `-3.12%`, и её влияние наблюдалось при переходе в Open Loop.

Практический вывод: при анализе OL учитывать накопленное learning и не считать каждый WB-vs-base mismatch чистой ошибкой MAF.

### ✅ CONFIRMED — MAF нужно разделять на CL и OL зоны

Рабочий процесс проекта:

- низ/середина MAF — анализ по CL trims;
- верх под нагрузкой — анализ по широкополосной лямбде;
- после правок проверять соседние точки кривой, а не только одну ячейку.

## Injector scaling

Исторически в проекте встречались значения scalar:

- `503.93 cc/min` — значение исходной калибровки;
- `541.25 cc/min` — тест;
- `552.12 cc/min` — тест;
- `564.93 cc/min` — тест.

Статус этих тестовых scalar не считать `stable` только по факту использования. Каждая итоговая версия должна быть привязана к конкретной ROM и логу.

## TGV

На автомобиле TGV hardware отсутствует: нет моторчиков/датчиков.

В ходе работы отключались DTC:

```text
P2004 P2005 P2006 P2007
P2008 P2009 P2011 P2012
P2016 P2017 P2021 P2022
```

Статус:

- отключение перечисленных DTC — выполненный этап;
- наличие `Base Timing Idle B @ 0x5B167` подтверждено, но его связь с TGV не доказана;
- вопрос о необходимости дополнительных изменений TGV-related compensation tables должен проверяться отдельно и не считается окончательно закрытым только отключением кодов.

## Knock monitoring

Для оценки детонации в проекте используются в связке:

- IAM;
- FBKC;
- FLKC;
- RPM;
- Engine Load;
- AFR;
- throttle;
- IAT/ECT.

Отдельное мгновенное значение knock-параметра без режима работы не является достаточным выводом.
