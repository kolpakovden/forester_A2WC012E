# ROM storage

ROM-файлы хранятся только с понятным статусом и описанием.

Проект относится к **Subaru Forester STI SH5, JDM / RHD, ECU A2WC012E**.

> Исторические BIN могут содержать `sg9` в filename. Такие имена сохраняются ради происхождения файла и связи со старыми логами. Это не означает совместимость с SG9.

Рекомендуемая структура:

```text
roms/
├── stock/
├── stable/
├── experimental/
└── rejected/
```

## stock

Исходные неизменённые ROM. Не перезаписывать и не заменять «почти стоковой» версией.

Желательно хранить для них SHA-256 и источник файла.

## stable

Только проверенные сборки с соответствующей записью в `CHANGELOG.md` и связанным логом.

Сам факт, что ECU принял запись и двигатель запустился, **не делает ROM stable**.

Минимум для stable:

- нормальный запуск;
- нормальная реакция на педаль;
- устойчивый ХХ;
- нет новых критичных DTC;
- проанализирован лог нужного режима;
- известен diff относительно базы;
- есть понятная точка отката.

Имя нового файла рекомендуется делать самодостаточным:

```text
A2WC012E_v0.4.0_maf-ol_tgv-delete.bin
```

Исторические файлы задним числом не переименовывать без необходимости.

## experimental

ROM для текущих тестов. Не считать безопасными только потому, что они находятся в репозитории.

Метки вроде `TEST`, `PRECHECK`, `EXPERIMENTAL` означают, что версия ещё должна пройти проверку.

Для experimental ROM желательно указать в `CHANGELOG.md`:

```text
Base ROM:
Что изменено:
Зачем:
Что ожидаем увидеть:
Какой лог нужен:
```

## rejected

Сборки, которые дали плохой результат. Сохранять для анализа diff и предотвращения повторения ошибки.

Для rejected ROM обязательно добавить причину в `docs/rejected-experiments.md`.

Rejected означает: **не использовать эту конкретную сборку как базу без отдельного разбора причины**. Это не обязательно означает, что сама идея или таблица навсегда признана неправильной.

## Перед прошивкой

Всегда проверить:

- имя и происхождение файла;
- к какой версии он относится;
- definition/ECU compatibility;
- ROM ID;
- статус версии;
- список изменённых таблиц;
- binary diff относительно базы;
- наличие заведомо рабочей ROM для отката.

Если файл имеет `PRECHECK` в имени, его нужно рассматривать как experimental до фактической проверки на автомобиле.
